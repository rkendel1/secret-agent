# Pi and Gemini CLI: source-grounded primitive review

Target system: a Rust agent with a deterministic core that plans and draws an edit boundary. The model writes whole files inside that boundary, and only tests or AppPort checks (plus hidden tests in evaluation) decide acceptance. It has pluggable context and recovery strategies, model output is never proof of success, and permissions and the boundary never widen on retry.

Method: shallow clones (`git clone --depth 1`). The files were only read, never installed or run. Paths are relative to each clone root, and line ranges refer to the commit listed. "not found" means a targeted search of the source turned up nothing.

## 1. Pi (pi-mono, `packages/coding-agent` + `packages/agent`)

- **URL:** https://github.com/badlogic/pi-mono
- **Commit:** `4954d760504c11df9b2cbdc040346107b6a8153d`
- **License:** MIT (`LICENSE`, "Copyright (c) 2025 Mario Zechner")

### Minimal tool set (what Pi actually exposes)

- **Default tools: `read`, `bash`, `edit`, `write`.**
  - `packages/coding-agent/src/core/system-prompt.ts:14,64` sets `selectedTools ?? ["read","bash","edit","write"]`.
  - `createCodingTools` / `createCodingToolDefinitions` in `src/core/tools/index.ts:164-171,195-202` build the same four.
  - `docs/cli.md:128` says "Default enabled tools are `read`, `bash`, `edit`, and `write`".
- **All built-in tools:** `read, bash, powershell, edit, write, grep, find, ls` (`src/core/tools/index.ts:95-105`).
  - `createReadOnlyTools` returns `read, grep, find, ls` (`index.ts:204-211`).
- **Opt-in built-in extensions:** `codemode` (QuickJS script tool), `tool_search` (BM25 over tool metadata) and MCP (`docs/sdk.md:116`; `src/extensions/tool-search/tool.ts:1-9`). They are registered inactive.
- **System prompt:**
  - One preamble sentence, a generated tool list, and a few rules: "Be concise", "Show file paths clearly".
  - Without grep/find/ls, it adds "Use bash for file operations like ls, rg, find" (`system-prompt.ts:88-125,155-161`).
  - Then come optional AGENTS.md context, skills and the cwd (`:172-186`).
- **Explicit omissions:** the README says "Pi ships with powerful defaults but skips features like sub-agents and plan mode" (`packages/coding-agent/README.md:19`).
- **Why this matters for the target:**
  - Pi shows that a frontier model can work with only read, shell and edit/write, and that the prompt can stay tiny.
  - Because of that, every behaviour (planning, verification, safety) is either left to the model or pushed into extensions.
  - The target takes the opposite route: the model gets no tools at all, and the core does discovery, planning and verification.
  - So Pi is a useful lower bound for prompt and tool overhead, and a counterexample to copy for control.
  - When Pi's model "decides it is done", that is not evidence of success.

## 3. The three most valuable ideas for the target, and how to run each as an experiment arm

1. **A paired-arm eval protocol with blocked-pair accounting** (Pi `packages/evals/src/plan.ts:39-59`, `src/docker.ts:90-123`, `src/report.ts:336-400`).
   - **What to build:** every comparison between context strategies (e.g. `minimal` vs `dependency-aware`) or recovery policies runs as `(task, arm, model, run)` tuples.
     - Each tuple gets a fresh read-only container.
     - Arm order alternates by run number.
     - An infrastructure failure becomes a *blocked pair* that withholds the headline number. It is never silently dropped and never retried until it passes.
   - **Measure:**
     - Lift = treatment minus control pass rate on hidden acceptance tests, over pairs that are not blocked.
     - Also report the blocked-pair count, the `flaky` / `saturated` / `negative-delta` flags, and tokens and wall time per pair.
     - Run with N ≥ 5 per arm to estimate variance.

2. **Deterministic repetition detection with a one-shot corrective escalation** (Gemini `services/loopDetectionService.ts:313-349`, `core/client.ts:776-793,1297-1328`).
   - **What to build:** hash each attempt's failure signature, e.g. (failing test IDs, normalized error lines, a diff hash of the emitted files).
     - The first repeat triggers one feedback retry that quotes the repeated failure.
     - A second repeat stops the run (`stop-on-repeated-failure`).
   - **Arms:** `feedback-retry (no stop)` vs `feedback-retry + signature-stop` vs `context-expanding retry + signature-stop`, all with the same maximum attempt budget.
   - **Measure:**
     - Final hidden-test pass rate and mean attempts/tokens used.
     - False-stop rate: runs stopped early that the no-stop control solved within budget.

3. **Pre-test structural gates on whole-file output** (Gemini `tools/omissionPlaceholderDetector.ts` with `tools/write-file.ts:709-711`; Pi length-truncation rejection at `packages/agent/src/agent-loop.ts:261-269,470-506`; Gemini `AllowedPathChecker` at `safety/built-in.ts:33-215` and the build-file taint rule at `tools/shell.ts:272-283`).
   - **What to build:** before any test runs, deterministically reject an attempt if any of these hold:
     - The output ended because of the token limit.
     - Any file contains elided-code placeholders.
     - Any path resolves outside the edit boundary or names a build or test config file.
   - A rejection is fed back as a failed attempt, with no widening.
   - **Arms:** gates on vs gates off (gates off still runs the tests).
   - **Measure:**
     - The share of attempts caught before testing, and test-runner time saved.
     - Change in final pass rate.
     - Any acceptance where hidden tests failed but visible tests passed after a test or build file was touched (should be zero with gates on).
