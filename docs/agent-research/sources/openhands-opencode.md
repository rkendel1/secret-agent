# OpenHands and OpenCode: what the source actually does, and what a deterministic-core Rust agent should take from it

Method: shallow clones (`--depth 1`), read-only inspection. Nothing was installed, built or run. Every path below is relative to the root of the repository named in that section's header, with line numbers as of the commit shown. "Not found" means I searched for it (by grep and by reading the directory) and it does not exist at that commit.

Target system (used for the recommendations): a Rust agent. A deterministic core plans each change and draws an edit boundary. The model writes whole files inside that boundary. Acceptance comes only from project tests or AppPort contract checks, plus hidden tests during evaluation. The agent compares context-selection strategies and recovery policies. Model output is never proof of success, and neither permissions nor the boundary widen on retry.

## 3. The three most valuable ideas for the target, as experiment arms

1. **Failure-signature stuck detection with one nudge, then stop.** Source: OpenHands `conversation/stuck_detector.py:192-248` and `local_conversation.py:751-774`, tested in `tests/sdk/conversation/local/test_stuck_detector_nudge.py`.
   - *Arm:* `stop-on-repeated-failure(N)`. The signature is (hash of the files written inside the boundary, sorted failing-test IDs plus normalized first error line). At N identical signatures, add one "this exact attempt already failed with …" note. At N+1, stop.
   - *Compared against:* fixed-k feedback retry, with the same k as the cap.
   - *Measured by:* hidden-test pass rate (must not drop), tokens and wall-clock spent on tasks that end unsolved (should drop), and the share of stops that were "correct". A correct stop is one where running to k would not have passed. Measure it by running every task to k offline and replaying the arm's decision.

2. **Deterministic budget ceiling plus bounded test-output digest.** Source: OpenCode `session/compaction.ts:95-100, 911-922` (window − max(10%, 16k), shrink 0.7/0.5/0.35); OpenHands `utils/truncate.py:50-80` (head and tail kept, full log saved) and the CODE_STATE/TESTS sections in `condenser/prompts/summarizing_system.j2`.
   - *Arm:* `feedback-retry` with the failing-test output digested to B tokens: head and tail plus the first assertion per failing test, with the full log kept only for the harness. B is chosen from the ceiling ladder.
   - *Compared against:* untruncated output, and output cut at a fixed character limit.
   - *Measured by:* pass@retry-1 and pass@retry-2 per budget B, prompt tokens per attempt, and the rate of context-overflow errors. Plot pass rate against tokens to find the knee.

3. **Path-triggered context expansion on retry, with an enforced boundary.** Source: OpenCode `tool/plugin/read.ts:82-108` (nearest AGENTS.md on touched paths); OpenHands `skills/trigger.py:39-47` with `local_conversation.py:593-640` (path rules injected when a file is touched); enforcement from OpenHands `file_editor/impl.py:42-55` and OpenCode `permission.ts:165-189`.
   - *Arm:* `context-expanding-retry`. On retry, the core adds instruction and contract files (AGENTS.md, AppPort contract specs) nearest to (a) files in the boundary and (b) the source files named in failing-test stack traces. The core does this deterministically; the model never requests it. The write allow-list is checked at execution, and an out-of-boundary write is rejected and counted, never applied.
   - *Compared against:* feedback-only retry, using the same seeds and the same budget.
   - *Measured by:* hidden-test pass rate at retry 2, tokens added per expansion, and boundary-violation attempts per task. Violations must be 0 applied in every arm and should not rise with expansion.
