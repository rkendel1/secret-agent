# Cline and Goose: source-grounded primitives review

Scope: the ten agent primitives, read from source and tests at the pinned commits below. Nothing in either repository was installed, built or executed. Paths are relative to each repository root, and line numbers apply at the stated commit. "Not found" means I searched for it and it is not in the tree. It does not mean the feature does not exist anywhere else.

Target system (for the recommendations): a Rust coding agent. A deterministic core plans the change and sets an edit boundary. The model writes whole files inside that boundary. Only tests and AppPort contract checks decide acceptance (plus hidden acceptance tests during evaluation). The system has interchangeable context strategies and recovery policies and an experiment harness. Hard rules: model output is never proof of success, and permissions and the boundary never widen on retry.

## 3. Three most valuable ideas for the target system

1. **Goose's `Operation` → `StepResult{effects, status}` pipeline as the recovery-policy substrate** (`crates/goose-agent/src/operation.rs:89-240`, `machine.rs:113-190`, composition in `crates/goose/src/agents/state_machine_builder.rs:68-133`). Each policy becomes one ordered, testable operation over persisted attempt state: `FeedbackRetry`, `ContextExpandingRetry`, `FreshResetRetry` (the Goose `ops_retry.rs` behavior) and `StopOnRepeatedFailure`. A policy can only emit effects and cannot touch the boundary or permissions, which enforces the never-widen rule structurally.
   *Experiment:* arms = {feedback-retry, fresh-reset-retry, context-expanding-retry}, each with the same attempt cap N. Hold the context strategy fixed. Metrics: hidden-acceptance pass rate, pass@1 vs pass@N on attempts, mean attempts-to-green, and tokens per solved task. Add a pass^k reliability measure over ≥3 seeds (Cline `evals/analysis/src/metrics.ts:27-77`).

2. **Tree-sitter symbol and call-graph indexing for dependency-aware context, with touched-directory hints for observed context** (Goose `analyze/parser.rs`, `analyze/graph.rs:35-113`, `hints/load_hints.rs:27-105`). It already exists in Rust with the same crates. Because edges are name-based heuristics (`graph.rs:243-286`), use them to rank which read-only context to include inside a fixed budget. The deterministic planner still sets the edit boundary.
   *Experiment:* arms = {minimal (target files only), observed (files and dirs touched by failing tests/stack traces + hint files), dependency-aware (target + call-graph neighbours to depth 1–2)}, all under the same token budget. Metrics: hidden-test pass rate, context tokens, **context recall** (share of files referenced by the reference solution that appear in context), and first-attempt compile/typecheck success.

3. **Canonical-signature repeated-failure detection with soft/hard thresholds** (Cline `sdk/packages/core/src/runtime/safety/loop-detection.ts:40-87, 125-161`, escalation in `session-runtime-orchestrator.ts:1460-1530`), applied to *failure signatures* rather than tool calls. The signature is a sorted, normalized set of failing test IDs and contract-check codes plus the normalized first error line. A soft hit switches policy (for example, feedback → context-expanding). A hard hit stops.
   *Experiment:* arms = {fixed N retries, stop after 2 identical signatures, soft-switch at 2 / hard-stop at 3}. Metrics: tokens and wall time saved per task, **false-stop rate** (tasks stopped early that the fixed-N arm eventually solved), and net pass rate. This shows directly whether early stopping costs solves.
